# Dữ liệu đầu vào

## Nạp case đầu tiên

1. **Chọn một mob và một hành vi bạn đã quan sát.** Ví dụ, mob tung đòn sau cảnh báo hoặc chuyển phase đúng một lần. Lấy Minecraft, nền và build server, Java, MythicMobs build/edition và phiên bản addon liên quan. `/mm version` cho phiên bản MythicMobs. [Lệnh MythicMobs](https://wiki.mythiccraft.io/mythicmobs/Commands-and-Permissions)
2. **Tạo thư mục `incoming/<ten-project>/<ten-case>/`.** Sao chép YAML mob và tất cả file thực sự được gọi như skill con, callback projectile, aura, item, summon hoặc spawner. Giữ đường dẫn gốc tương đối và ID nội bộ. Với pack, kèm phần `packinfo.yml` liên quan nếu có. Với ModelEngine, kèm model ID, state và mốc chạm đòn. Chỉ đưa vào bản sao đã bỏ khóa, mật khẩu, địa chỉ riêng và dữ liệu người chơi. [Files and Directories](https://wiki.mythiccraft.io/mythicmobs/Guides/%28Step-2%29-Files-And-Directories), [ModelEngine State](https://wiki.mythiccraft.io/modelengine/Skills/Mechanics/State)
3. **Sao chép [mẫu hồ sơ](TEMPLATE.md) thành `README.md` của case.** Điền yêu cầu, hành vi đã quan sát, bước tái hiện và đường dẫn bằng chứng. Thêm log khởi động/nạp hoặc một đoạn video có thời điểm. Với lỗi, để bản lỗi và bản sửa trong hai thư mục con, ghi cùng bước thử để đối chiếu.
4. **Dùng [prompt phân tích YAML](../prompts/02-hoc-tu-yaml.md).** Gửi đường dẫn thư mục case. Codex sẽ dò ID và phụ thuộc, vẽ lại luồng trigger → target → timing → animation → hitbox/damage → cooldown → interrupt/cleanup bằng chữ và đối chiếu wiki theo build đã ghi. Khi thiếu log hoặc thiếu phiên bản, ghi rõ phần suy luận và phần cần thử.
5. **Chạy [kiểm thử](../tests/README.md) trên bản sao server.** Bắt đầu bằng parse YAML, sau đó xác nhận plugin đã nạp định nghĩa. Thực hiện đúng trigger, với cả kịch bản có và không có mục tiêu, các nhánh điều kiện và trường hợp multiplayer nếu liên quan. Cập nhật hồ sơ bằng kết quả thực tế và trạng thái.
6. **Đưa case có bằng chứng vào `examples/`.** Chọn [simple](../examples/simple/README.md), [advanced](../examples/advanced/README.md), [bosses](../examples/bosses/README.md) hoặc [modelengine](../examples/modelengine/README.md) theo hành vi chính. Lưu YAML và README đi kèm khi đã có bằng chứng YAML dùng được. Nếu mới có kiểm tra cú pháp, giữ hồ sơ trong `incoming/` để bổ sung bằng chứng. Dẫn case từ [Knowledge Base](../knowledge/README.md) khi đã rút ra được quy tắc có nguồn. Dùng [template correction](../feedback/corrections/TEMPLATE.md) nếu xác nhận một lỗi cũ.

Lô đầu tiên chỉ cần một file mob, các file skill mà nó gọi, một README đã điền và phần log liên quan nếu có. Mỗi hồ sơ mới nên ghi đúng build đã dùng cho lần thử đó.
